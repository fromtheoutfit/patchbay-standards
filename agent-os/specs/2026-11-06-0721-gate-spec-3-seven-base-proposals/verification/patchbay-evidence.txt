### Install a required-version or latest (default)

```yaml
- name: Install the latest version of uv
  uses: astral-sh/setup-uv@07a047e608db84b3d8c06cd9a7c7dcc9c355c18e # v10.3.2
```

If you do not specify a version, this action will look for a [required-version](https://docs.astral.sh/uv/reference/settings/#required-version)
in a `uv.toml` or `pyproject.toml` file in the repository root. If none is found, the latest version will be installed.
  uses: astral-sh/setup-uv@07a047e608db84b3d8c06cd9a7c7dcc9c355c18e # v10.3.2
  with:
    # The version of uv to install, e.g., "0.5.0", "latest", or "latest-known" (default: searches for version in config files, then latest)
    version: ""

    # Path to a file containing the version of uv to install, e.g., uv.toml, pyproject.toml, .tool-versions, requirements.txt or uv.lock. A selected .tool-versions file can also provide the Python version (default: searches uv.toml then pyproject.toml)
    version-file: ""
### Working directory

You can set the working directory with the `working-directory` input.
This controls where we look for `pyproject.toml`, `uv.toml` and `.python-version` files
which are used to determine the version of uv and python to install.

It also controls where [the venv gets created](#activate-environment), unless `venv-path` is set.

```yaml
- name: Install uv based on the config files in the working-directory
  uses: astral-sh/setup-uv@07a047e608db84b3d8c06cd9a7c7dcc9c355c18e # v10.3.2
  with:
    working-directory: my/subproject/dir
```

# The one configuration file of this repository: every tool is configured under [tool.*] here and
# nowhere else (no setup.py, setup.cfg, requirements*.txt, tox.ini, .flake8, mypy.ini, pytest.ini

#
# Two kinds of section. [project], [build-system] and [dependency-groups] are the package's and
# change in any spec; adding a dependency is a Decision in that spec's shape.md (what it does, why
# the standard library cannot, its license). The [tool.*] sections are the gate's: [tool.uv] pins
# the uv that gate steps 2-5 of scripts/gate.sh run under, [tool.uv.build-backend] names the module
# step 2's sync installs, and the rest are the rule set those steps read (ruff format, ruff check,
# mypy, pytest). They are gate files and change only in the gate's own spec, with a person
# (agent-os/standards/base/process/verification-gate.md, "Pinned" and "The gate's own files change
# only in their own spec").
requires = ["uv_build>=0.13.7,<0.14.0"]
build-backend = "uv_build"

# The uv every uv command in this repository runs under; any other uv refuses to run here, so a
# local `--locked` run and CI's read uv.lock with the same uv (gate step 2's sync fails by name,
